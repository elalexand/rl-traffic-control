# rl-traffic-control
# Multi-Agent Reinforcement Learning for Traffic Signal Control in SUMO-RL (3x3 Grid)

Этот проект исследует применение методов многоагентного обучения с подкреплением (MARL) для адаптивного управления светофорами в симуляторе дорожного движения SUMO. Каждый перекрёсток моделируется как независимый RL-агент, который наблюдает локальную дорожную обстановку и управляет фазами своего светофора.

## Структура проекта

Проект состоит из одного Jupyter-ноутбука:

| Файл | Описание |
| :--- | :--- |
| `sumo_rl_3x3.ipynb` | Основные эксперименты, тюнинг гиперпараметров, тюнинг функций наград и сравнение алгоритмов на синтетической сети 3x3 |

## Окружение

Используется синтетическая дорожная сеть **3x3 Grid** из библиотеки SUMO-RL:

- **9 перекрёстков**, расположенных в виде сетки Манхэттена
- Однородная топология и структура трафика
- Входной поток: `routes14000.rou.xml` (14 000 машин)
- Длительность обучения: 2 000 секунд симуляции
- Длительность оценки: 4 000 секунд симуляции

Каждый светофор — отдельный RL-агент. На каждом шаге агент:

1. **Наблюдает** локальное состояние:
   - текущая фаза светофора
   - плотность машин на полосах
   - длины очередей
   - ограничения на переключение фаз
2. **Выбирает** следующую **зелёную** фазу
3. **Получает награду**, основанную на эффективности трафика

SUMO автоматически вставляет жёлтые переходные фазы между переключениями.

## Алгоритмы

В проекте сравниваются четыре подхода:

| Метод | Тип |
| :--- | :--- |
| **Random Policy** | Стохастический базовый уровень |
| **Fixed-Time Control** | Правило-ориентированный контроллер (фиксированный цикл) |
| **IMPALA** | Actor-critic от DeepMind |
| **MAPPO** | Multi-Agent PPO (Proximal Policy Optimization) |

Все RL-агенты используют **общую политику** (`shared_policy`), что ускоряет обучение и позволяет модели обобщать опыт со всех 9 перекрёстков.

## Тюнинг функций наград

Помимо дефолтной награды (минимизация времени ожидания), тестировались четыре альтернативные функции:

| Функция | Формула | Лучший результат |
| :--- | :--- | :--- |
| **Default** | `(prev_wait - curr_wait) / 100` | MAPPO: 0.6684 / IMPALA: 0.6443 |
| **Pressure** | `-r * pressure / 100` | MAPPO: 0.6444 / IMPALA: 0.6640 |
| **Queue** | `-k * queue / 100` | MAPPO: 0.6448 / IMPALA: 0.6396 |
| **Pressure + Queue** | `-α * pressure / 100 - β * queue` | MAPPO: 0.6445 / IMPALA: 0.6378 |
| **Combined** | `+a*speed - b*wait - c*queue` | MAPPO: 0.6661 / IMPALA: 0.6641 |

**Вывод:** дефолтная награда показала себя лучше или на уровне альтернативных. Комбинированная награда близка по качеству, но не превосходит дефолтную.

## Метрики оценки

Используются четыре метрики:

| Метрика | Описание |
| :--- | :--- |
| **Mean Speed** | Средняя скорость машин (м/с) — больше = лучше |
| **Mean Waiting Time** | Среднее время ожидания (сек) — меньше = лучше |
| **Mean Queue Length** | Средняя длина очереди (машины) — меньше = лучше |
| **Total Waiting Time** | Суммарное время ожидания — меньше = лучше |

**Итоговый балл:**

```python
score = mean_speed - 0.001 * mean_waiting_time - 0.1 * mean_queue_length
```

## Результаты финального сравнения

| Метод | Mean Speed | Mean Waiting Time | Mean Queue Length | Score |
| :--- | :--- | :--- | :--- | :--- |
| **Random** | 0.279 | 784.65 | 9.17 | -1.4224 |
| **Fixed-Time** | 0.379 | 84.99 | 3.66 | -0.0723 |
| **IMPALA** | 0.046 | 37 365.37 | 66.13 | -43.9332 |
| **MAPPO** | **0.692** | **3.28** | **0.44** | **0.6442** |

### Выводы

- **MAPPO** — лучший алгоритм. Он стабильно сходится, обеспечивает максимальную скорость, минимальные очереди и минимальное время ожидания. Значительно превосходит Fixed-Time и Random.
- **IMPALA** — нестабилен. На обучении показывает прогресс (reward растёт с -235 до -110), но при финальной оценке полностью «коллапсирует»: скорость падает до 0.046, очереди вырастают до 66 машин. Это классический пример training collapse в off-policy алгоритмах при плохо настроенной среде.
- **Fixed-Time** — простая и достаточно эффективная базовая линия. Уступает MAPPO в 3–4 раза по качеству, но превосходит Random.
- **Random Policy** — наихудший результат, как и ожидалось.

## Итоговый вывод

Проект демонстрирует, что **Multi-Agent PPO (MAPPO) является наиболее эффективным и стабильным алгоритмом** для управления светофорами в синтетической сети 3x3. Дефолтная награда (минимизация времени ожидания) показала себя лучше альтернативных функций награды. IMPALA без дополнительной стабилизации (например, gradient clipping, изменение размера батча или числа EnvRunners) не подходит для данной задачи.
